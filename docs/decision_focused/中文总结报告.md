## 二、三个目标各自的结论与关键数据

### 目标 2（先做，因为它是目标1的前提）：修改环境，注入时间自相关

**结论：能造出时间自相关，但转化不了——而且"提高自相关"这件事本身是自我拆台的。**

- **DF1（能力，`e0c59a7`）：** 关键发现是——生产信道**本来就开了** 3GPP TR 37.885 阴影衰落
  （`operating_point_regime` 里 `shadowing_37885=True`），你之前看到"恢复弱"不是因为信道是确定性的，而是
  **衰落退相关太快**：`dt=1s`、城市车速下每帧位移 ≳ 10m 退相关距离，`ρ_frame ≈ exp(−v·dt/d_corr) ≈ 0.37`，
  几乎逐帧独立。我把退相关距离 `SHADOW_DECORRELATION_DISTANCE_M`（原来是硬编码常数）暴露成可扫描的 config 旋钮
  `shadow_decorrelation_distance_m`（默认 10m，byte-identical）。

  | d_corr (m) | 10 | 25 | 50 | 100 |
  |---|---|---|---|---|
  | 决策关键 psucc 的滞后-1 自相关 ρ | 0.044 | 0.314 | 0.391 | 0.429 |

  **两个关卡都过：** ρ 随 d_corr 单调上升（+0.384，CI 分离）；且 psucc 的**边际分布不变**（成功率 0.64–0.67，
  无单调漂移，最大 KS ≤ 0.031）——即旋钮只动"自相关"，不动"难度"（这是对抗性评审专门盯的混淆项，实测排除）。

- **DF2（关卡，`40c6962`）：** 在真实部署管线里重跑 oracle。关键、稳的证据是——
  **`feas(realizable) == feas(stale)`**（各 d_corr 差值 `{+0.000, −0.009, +0.000, +0.003, +0.000}`），
  **同时** `MSE(realizable) < MSE(echo)`（CI 不重叠）：一个**真实的逐边 MSE 改善，却带来零 feasibility 变化**——
  就是"MSE ⊥ 决策"在环境旋钮下的复现。真值 oracle 能转化（headroom CI-positive，5/5 种子）。
  - **归因（df2b，非同义反复）：** 加了一个**纯时序臂**（两个 stale 滞后、无距离）。它对决策的贡献 ≤0.006（各 ρ），
    随 ρ 上升 MSE 优势还缩小；唯一有点用的是**当前几何（距离）**，且只在**低 ρ**才有（+0.044，随 ρ 缩小）。
  - **机制：** 提高时间自相关是**自我拆台**的——让信道"可预测"的那个相关性，同时也让 **stale echo 本身变准**
    （`MSE(echo)` 从 0.27 塌到 0.03），于是可恢复的净优势随 ρ 反而缩小。
  - **对抗性验证：** 3-critic Workflow 判 REVISE / conclusion_robust=TRUE，把 v1 的过度断言全部收敛（改锚在
    point-identity 上；ρ 只到 0.42、更高 ρ 未测；几何 vs 时序用新臂非同义反复地证明）。

### 目标 1（headline）：Decision-focused CSI prediction

**结论：你的强假设被否定；弱版本因样本不足而不确定。**

我实现了 **BWAR**（Boundary-Weighted Asymmetric Regret-surrogate：边界加权回归 + 关于 0.4/0.6 门限的非对称
错侧 hinge + 侧分类辅助），用真值 psucc 当训练标签、推理只用 leak-free 特征、门限 τ 与部署 anchor 同一套代码
（train==deploy）。

- **强结论（统计功效充足，CI 排除 0）：** **没有任何可实现目标（纯 MSE 或任何决策聚焦变体）能接近真值 oracle。**
  配对 `true − mse = +0.131`，CI `[0.079, 0.184]`，5/5 种子，**p = 0.0022**。⇒ 你的假设——"决策聚焦目标能把
  stale-drop 转化回来"——**被否定**；瓶颈是**特征里的信息**（aleatoric）。
- **弱结论（样本不足，不确定）：** 决策聚焦相对 MSE 有没有一个**小的**净增益，n=5 下**测不出来**：三个变体点估计都
  是负的，但每个 CI 都跨 0（p=0.11–0.41；对 +0.03 效应功效仅 ~10–25%）。方向为负，但不是"证明为零"。

  | 实验 | 结果 |
  |---|---|
  | df3 默认 BWAR | `bwar−recal_mse = −0.038` CI[−0.088,+0.013]；重标定控制臂 == mse（无标定增益） |
  | df3b 10-配置 val 扫描 | `mse_equiv`（决策聚焦关掉）不劣于任何 BWAR 变体；`valbest−mse = −0.014` CI[−0.057,+0.028] |
  | df3c marginal-slot（预算边缘加权） | `−0.031` CI[−0.089,+0.027] |
  | df3d **B.3(iii) 投入度审计** | BWAR **确实投入了**决策方向（echo-错边上 dir_acc +0.079，4/5 种子），但两者都**低于随机**（0.40 vs 0.32）→ engaged-but-aleatoric |

- **对抗性验证抓到一个关键漏洞：** critic 发现我原来声称"预注册关卡全满足"，但 B.3(iii)（证明目标真的作用到了
  决策关键边）**从没跑过**；而 BWAR 抬高了全局 MSE，这既可能是"聚焦到边界"、也可能是"目标根本没起作用"。于是我**补跑
  了 df3d**：结论是 BWAR **确实起了作用**（方向精度 +0.079），但即使起作用，那些难边上信息也不够（都 < 随机）→
  这才是正确的"投入了但信息瓶颈"的诚实负面，而不是"没调好"的过早负面。Workflow 判 REVISE / conclusion_robust=FALSE，
  已按要求把"provably refuted / 三重确认"降级为"强结论（oracle 差距无法跨越）+ 弱结论（小效应不确定）"。

### 目标 3：leaky-tanh 是不是最好的？为什么不用 softmax？

**结论：per-edge logit 用 leaky-tanh 是对的；softmax 对这个机制是"范畴错误"。**（DF4，`731b1b7`）

- **leaky-tanh 好在哪：** per-edge 残差 logit 需要两条性质——(a) 有界（信赖域/PPO 稳定）；(b) 梯度不消失（时序信号
  能到达"被执行的" logit，这就是 T2 修的饱和缺陷）。leaky-tanh 两条都满足。对比：普通 tanh/hardtanh 饱和；identity
  无界不稳；relu/softplus 单边（不能把 logit 推负）；**softsign 是退步**（梯度仍趋 0）。唯一有力对手是"小尺度线性+
  幅度惩罚"（软约束 vs leaky-tanh 的硬约束）。→ **保留 leaky-tanh。**
- **为什么不用 softmax（实测确认）：**
  - **在部署端它什么都改不了（Test 1）：** softmax 对入射边 logit 是单调的，所以它的 top-b 选择与 sigmoid/psucc
    的 top-b **完全一样**——`softmax top-b == anchor 0.9935`（928 个 node-frame，剩下 0.6% 是并列）。它只在
    训练梯度上不同（而那个 `−p_i p_j` 的耦合梯度对独立边是错的）。
  - **它破坏 cross-N / 多边（Test 2 = 范畴错误）：** N 条等 psucc 入射边时，softmax 每边保留质量 = `1/N`
    `{0.50, 0.25, 0.125, 0.0625, 0.042}`（N=2..24），而 sigmoid/tanh 是 N-无关的 `0.5`。softmax 会让高度数节点
    连接不足、无法"一次保留多条边"——对预算-topk-多边-跨N 的决策是致命的。
  - softmax **该用**的地方是另一个机制（edit-selection，对候选编辑做分类选择）。但本战役证明 edit-selection 也没用：
    它要排序的方向信号在决策关键边上低于随机（df3d），把 belief 注进 anchor 排序（这就是 edit-selection）等于 stale
    echo（DF2/DF3）。⇒ **激活/头的选择在 feasibility 层面是无关紧要的**——anchor 是所有可部署臂的天花板。

## 三、中心科学发现（三目标合流）

把三个目标放到一起看，它们**互相印证同一堵墙**：

> **在 anchor 的决策边界上，可部署的精度受限于 leak-free 特征里的信息量本身（aleatoric / 信息瓶颈），
> 而不是受限于训练目标、环境的时间结构、或输出激活。**

证据链：真值 CSI 能转化（+0.131，p=0.0022，功效充足）→ 决策**是**可从完美 CSI 恢复的；但（目标1）换任何目标都到
不了 oracle；（目标2）把环境时间自相关拉高也转化不了、而且自我拆台；（目标3）换激活/头在部署端根本不改变决策。三条
路都堵在"信息不在特征里"。这把项目一直以来的"N≤16 可部署精度墙"最终定位到了**信息层面**。

## 四、可部署建议

1. **保留 plain MSE** 作为 belief 目标；**不采用** BWAR（无可检出增益，默认关）。
2. **保留 leaky-tanh** per-edge 残差头（opt-in，默认 byte-identical）；**不要**对 per-edge logit 用 softmax。
3. **保留** `shadow_decorrelation_distance_m` 旋钮（物理真实、opt-in、默认 byte-identical）作为研究工具，但它
   **打不过 anchor**。
4. 没有可部署的学习臂超过 `local_hysteresis` anchor —— 与前 5 个战役一致，anchor 仍是 N≤16 的可部署上界。

## 五、开放前沿（若要继续攻这堵墙，只有信息侧有希望）

既然瓶颈是"信息不在 leak-free 特征里"，唯一有希望的方向是**增加可部署的信息**，而不是再换目标/环境/结构：
- 给部署端**更多可观测量**（多跳邻居广播、更长的 stale 历史、显式 AR 阴影状态估计）——但要严格 leak-free 验证。
- 或降低 anchor 决策边界对精度的敏感度（例如更宽的 hysteresis 带、显式不确定性下的保守决策）。
- 更大 N（≥24）配一个更便宜的精确-故障评估器——检验墙是否随 N 变化。
